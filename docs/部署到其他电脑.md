# 部署到其他电脑

> 2026-11-09。给"另一台机器要能跑起来"这件事收个口。
> 结论先说：**代码部分可以照抄，但有四件事每台机器必须自己做**，漏一件就跑不起来。

## 一、能自动兜住的（代码已经处理，不用管）

| 问题 | 现在怎么处理 |
|---|---|
| 本机没装 Chrome | 自动回退：chrome → msedge → chromium → 默认内核 → 扫已下载的 Chromium → 扫已装的 Chrome/Edge |
| Playwright 版本与已下载浏览器不一致 | 直接扫 `ms-playwright/chromium-*` 用已有的，不看版本号 |
| Playwright 内核都没装 | 报 `SOLDEAZY_BROWSER_LAUNCH_FAILED`，提示 `uv run playwright install chromium` |
| profile / TEMP 目录不存在 | 启动时自动创建 |
| 浏览器启动被沙箱拒绝 | 报 `SOLDEAZY_BROWSER_LAUNCH_DENIED`，指出是 profile 还是临时目录没权限 |
| 登录态丢失 | 登录后 cookie 落盘（含会话级），下次启动先恢复再访问 |
| 无头模式下没凭据 | 立即报 `SOLDEAZY_CREDENTIALS_MISSING`，不再干等 120 秒 |

## 二、每台机器必须自己做的四件事

### 1. 装依赖

```powershell
git clone https://github.com/zhan-1002/eBay-mcp.git
cd eBay-mcp
uv sync --extra dev --extra soldeazy
```

> `--extra soldeazy` 不能省，它带 openpyxl 和 playwright。

### 2. 建 `.env`（不入库）

```dotenv
# Soldeazy 登录凭据：没有它就只能人工登录
SOLDEAZY_USERNAME=你的账号
SOLDEAZY_PASSWORD=你的密码

# eBay 官方 API（只有用到 ebay_* 工具才需要）
EBAY_CLIENT_ID=
EBAY_CLIENT_SECRET=
```

`.env` 已在 `.gitignore` 里，不会被提交，**每台机器要单独建**。

### 3. 配置 MCP 客户端

以 WorkBuddy 为例，`~/.workbuddy/mcp.json`：

```jsonc
"ebay": {
  "type": "stdio",
  "command": "<uv.exe 的绝对路径>",
  "args": ["--directory", "<仓库绝对路径>", "run", "ebay-mcp-server"],
  "env": {
    "PYTHONUTF8": "1",
    "PYTHONIOENCODING": "utf-8",
    // 关键：数据目录放在**工作区内**，沙箱才放得行
    "SOLDEAZY_PROFILE_DIR": "<仓库绝对路径>\\.soldeazy-data\\profile",
    "TEMP": "<仓库绝对路径>\\.soldeazy-data\\temp",
    "TMP": "<仓库绝对路径>\\.soldeazy-data\\temp",
    "TMPDIR": "<仓库绝对路径>\\.soldeazy-data\\temp",
    "SOLDEAZY_BROWSER_CHANNEL": "chrome",
    "SOLDEAZY_HEADLESS": "1",
    "SOLDEAZY_WRITE_ENABLED": "1"
  },
  "timeout": 180000
}
```

`.soldeazy-data/` 已在 `.gitignore`，里面是登录态，不要提交。

### 4. 沙箱放行（只有沙箱化的客户端需要）

如果客户端（如 WorkBuddy）会给 MCP 进程套沙箱，必须让它对数据目录可写。
WorkBuddy 在 `~/.workbuddy/settings.json`：

```json
"sandbox": { "extraAllowWrite": [
  "~/.ebay-mcp",
  "~/AppData/Local/ebay-mcp",
  "~/AppData/Local/uv/cache"
]}
```

> 实测：沙箱**只允许写工作区**。所以第 3 步把数据目录放在仓库内，
> 是同时满足"沙箱可写"和"不入库"的最省事做法。
> 改完 `settings.json` 需要重启客户端才生效。

## 三、部署后自检

调一次 `soldeazy_status`，重点看这两块：

```json
{
  "credentials_configured": true,
  "session_file_exists": false,     // 首次为 false，登录后变 true
  "session_save_error": "",
  "dirs": {
    "profile": { "writable": true },
    "temp":    { "writable": true }
  }
}
```

- `dirs.*.writable = false` → 沙箱没放行，或路径不在工作区
- `credentials_configured = false` → `.env` 没建或没被读到（注意 cwd 必须是仓库）

再调一次 `soldeazy_list_shops`，它会真正启动浏览器：

- 成功 → 返回渠道账号列表
- `SOLDEAZY_BROWSER_LAUNCH_DENIED` → 权限问题，看 `dirs`
- `SOLDEAZY_BROWSER_LAUNCH_FAILED` → 真的没浏览器，`uv run playwright install chromium`

## 四、已知的平台差异

| 项 | Windows | 说明 |
|---|---|---|
| 浏览器 | Chrome / Edge 必有其一二 | 代码六层回退，一般不用装 |
| 路径含中文/空格 | 支持 | 已在含中文和空格的仓库路径上验证 |
| 沙箱 | 常见 | 数据目录必须落在工作区内 |

## 五、不要做的事

- **不要**把 `.env`、`.soldeazy-data/` 提交到仓库（含账号密码和登录 cookie）
- **不要**把 `SOLDEAZY_PROFILE_DIR` 指到 `%LOCALAPPDATA%` 后又在沙箱里跑——
  沙箱会拒绝写入，表现为浏览器启动 EPERM
- **不要**同时跑两个实例指向同一个 profile，会锁死（`profile_ready` 正常但仍失败）

## 六、多个会话要共用：为什么 stdio 做不到

"全局安装"只共享代码，不共享浏览器。Soldeazy 链路额外依赖一个**登录态目录**
（`SOLDEAZY_PROFILE_DIR`），而 Chromium 规定一个 user-data-dir 同一时刻只允许
**一个进程**打开。stdio 模式下每个会话各自起一个 `ebay-mcp-server` 进程，
第二个进程必然抢不到 profile——表现为所有 `soldeazy_*` 工具报错，
与装没装全局、装在哪无关。

旧版本把这个抢锁失败误报成 `SOLDEAZY_BROWSER_LAUNCH_FAILED`（"找不到 Chrome"），
2026-11-11 起改报 `SOLDEAZY_PROFILE_LOCKED`，消息里直接给两条出路：

1. **常驻一个服务进程**（推荐）：

   ```powershell
   ebay-mcp-server --transport sse
   ```

   所有客户端/会话都连同一个 SSE 地址。浏览器只被这一个进程持有，
   多会话天然共享登录态，也顺带省掉每会话重复启动浏览器的几十秒。
2. **接受单会话 + 空闲自动释放**（2026-11-11 起的默认行为）：
   浏览器空闲 `SOLDEAZY_BROWSER_IDLE_SECONDS`（默认 300 秒）后自动关闭，
   **profile 锁随之交还**——上一个会话用完 5 分钟，下一个会话就能接上，
   且不用重新登录（关闭前 cookie 已落盘）。搜索进行中被占用会顺延，不会掐业务。
   代价是会话之间不能"同时"用，只能"接力"用。
3. **每会话一个 profile 目录**（不推荐）：登录态不共享，每个会话都要重新登录一次。
