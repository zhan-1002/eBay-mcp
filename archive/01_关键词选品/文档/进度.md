### 改了什么

1. `collect_ziniao.py::set_ship_to` 重写：**只在弹层容器内**找国家/邮编控件，不点提交型按钮，返回 dict 如实反映成败。
   - 原实现最后一个邮编兜底是 `input[type='text']`，会命中**全局搜索框**，把 `SW1A1AA` 填进搜索框并提交，把页面带跑到"搜 SW1A1AA 商品"（实测复现，并导致后续 `goto` 卡满 180s）。
   - 原实现无条件 `return True`，"配送弹层已点"是假信号。
   - 现状：弹层识别不到就明确告警并只用 URL 的 `_stpos/_fcid` 兜底，日志显示 `country_ok=False zip_filled=False` —— 至少不再谎报。
2. 列表解析改用 `li.s-card` 多选择器兜底；跳过占位卡与已下架条目。
3. 价格解析 `parse_price_display`：区间取 min/max（新增 `price_max`/`price_is_range`），并修正欧陆数字格式（旧实现把 `,` 一律删掉，`12,99` → `1299`）。
4. 广告位/末级类目改由内嵌 `listings` JSON 提供（按 itemId join），不再扫 card HTML 找 "sponsored"（旧做法会虚高）。
5. `120 条` 循环补 `need<=0` 直接退出，不再把"配额已满"误判成"本页无结果"。
6. 详情页 specifics 改走 `#viTabs_0_is dl/dt/dd`，并过滤物流类噪音（Postage/Returns/Collection/Condition 不再混入）。
7. `analyze.py::generate_titles` 按原脚本 `ebay_zc/ziniao_ebay_search.py::build_recommended_titles` 的结构重写：属性短语堆叠 + 修饰词组合，硬约束 ≥18/≤80 字符、无逗号、同标题不重复词；品牌词由 `detect_brands` 从语料自动识别并剔除（原脚本是硬编码测试品清单）。三段重试保证"至少 20 条"不被多样性护栏削减。
8. 导出新增 `price_range_display` 与 `可加第二类目` 两列。

## 2026-09-14（下午）：详情页改为不采，改采 item id 交给下游

用户决定：**详情页不采**，用 item id / 链接到别的系统取 item specifics。

### 风控依据（实测，不是推测）

120 条详情页 = 120 次商品页访问，全部走登录态的英国店，风险落在账号上。已实测到的风控信号：

| 现象 | 出处 |
|---|---|
| `net::ERR_CONNECTION_CLOSED` | 某次详情页 goto 被 eBay 侧断连 |
| `TargetClosedError: browser has been closed` | 某次跑批中途会话被关 |
| 业务脚本自身已有"状态 7：eBay 反爬挑战页"分支 | `ziniao_ebay_monthly_bill.py::detect_state` |

**结论：不采详情页。** 120 条详情页无必要 —— 广告位(`promoted`)与末级类目(`leafCat`)来自搜索页内嵌 JSON，120/120 零额外请求；下游按 item id 自己取 specifics。

### 改动

- `--detail` 默认值 `10` → **`0`**（不进详情页；需要时才显式传 `--detail N`）
- `collect_on_page` 在 `detail_n=0` 时明确打印并跳过详情段
- 导出「采集明细」列顺序调整：`position, item_id, legacy_item_id, variant_id, item_url, title, price, price_max, price_range_display, currency, is_sponsored …` —— 把下游对接要的标识列提到最前面

### 实测结果（`detail=0`，只 1 次搜索页加载）

```
120 条 / 唯一 item_id 120 个
item_id       120/120   legacy_item_id 120/120   item_url 120/120（全部含 /itm/数字）
variant_id     54/120   search_rank    120/120
广告位 promoted=True 13 条，标记来源全部 = listings（不是 DOM 猜的）
末级类目 ID   120/120（112529:109, 80077:5, 14990:4, 171821:1, 183074:1）
价格非空      120/120（min/p50/max = …），本批无区间价
title a11y 噪音 0 条 ; 推荐 title 20 条
产物：输出/haihu_8075_uk_wireless_earbuds_20260914_120256.xlsx（10 sheet）
```

### 期间修掉的两个真 bug（详情页那次"只落 1 条"的根因）

**Bug 1：CDP 接管时序** —— `open_store` 给了 `debuggingPort` 后浏览器窗口并不立即可连，实测**连续 5 次全 ECONNREFUSED**。原代码 `sleep(10)` 后直接连，全靠运气；运气差的 run 里第 1 条详情侥幸成功、**第 2~10 条全部静默失败**（`fetch_item_detail` 只对 goto 做 try/except，失败即 return，一句日志都没有）。

- `ziniao_runtime.py` 新增 `wait_for_cdp()`（轮询等端口可连）与 `connect_cdp()`（就绪等待 + 90s 重试），`run_keyword_research.py::run_ziniao` 改用它
- `kill_ziniao()` 改为**确认杀干净**（原实现 kill 一次 + sleep(3)，残留进程占住紫鸟单实例锁 → 下一次"紫鸟服务启动超时"）
- `fetch_item_detail` 失败不再静默
- 修复后实测：前 10 条 specifics **10/10** 落地（13/19/27/16/13/18/12/8/7/16 项）

**Bug 2：类目名称路径取不到** —— 一直假设面包屑是 `/b/xxx/数字`，实际 2026 版是：

```html
<a class="seo-breadcrumb-text" href="https://www.ebay.co.uk/b/bn_7000259660"><span>Electronics</span></a>
  → Sound & Vision → Portable Audio & Headphones → Headphones
```

`bn_*` 非数字形态，原正则永远匹配不到。已改为"两处合并"：**类目数字 ID 取搜索页 `listings.leafCat`**，**类目名称路径取详情页面包屑**（`EXTRACT_JS` 已支持 `bn_` 形态，新增 `breadcrumb` / `category_path` 字段）。因改为不采详情页，该路径当前未启用。

### 另一处非代码教训

`set_ship_to` **不是**浏览器崩溃的原因（专门验过：它之后页面 `evaluate` 正常、搜索页 242 张卡正常）。它的问题只是**没设成**：点到 `button.gh-flyout__target`，弹层容器选择器 `[role='dialog']` 命中 137 个元素、抓到的"弹层"其实是页头，最终靠 `_stpos/_fcid` 兜底。

原边界（`build_price_table` 自动等分）极差 **30.0 个百分点**，一头挤一头空。改为固定整数段：


依据：分位 p25=8.59、p50=13.82、p75=17.01，边界咬住分位；保住 £14 峰（25 条）与 £8-9 峰（17 条）；整数边界便于业务沟通。

**踩坑记录（已加回归测试）**：合表用 `write_sections` 时把 **dict 行直接传进去**，Python 迭代 dict 得到的是**键**，

### 推荐标题：质量仍不达标（已知限制，待决）

## 2026-09-15（五续）：eBay 凭据持久化 + 标题清洗口径修正

### 一、凭据为什么续不上，以及怎么修

原来 `token.local.txt` 存的是 **access token**（用户访问令牌）。它只有 **2 小时**寿命，
而且**本身不可续期** —— 所以每次跑都要人重新生成再贴一遍。**不是脚本写得烂，是存的东西类型不对。**

能持久的只有两种：**refresh token**（约 18 个月，授权码流程拿一次）或
**client_id + client_secret**（长期，可随时换 app token）。

新增 `脚本/ebay_auth.py`：

| 能力 | 说明 |
|---|---|
| 令牌缓存 | `02_soldeazy详情补数/token.local.json`（带 `expires_at`，被 `*token*.json` 覆盖进 gitignore） |
| 自动续期 | 2 小时内复用；**提前 5 分钟**用 refresh_token 换新的 |
| 401 自愈 | `_get` / `getItem` 收到 401 → 换令牌**重试一次**，长任务不再中途崩 |
| 来源拉黑 | 被 401 否掉的来源本次运行内跳过 → 自动往下一条路走（贴了过期令牌也不卡死） |
| 并发安全 | 内部加锁，8 线程同时 401 也只会去换一次令牌 |
| 原子写 | 临时文件 + `os.replace`，不会留下半个缓存文件 |

取令牌顺序：显式参数 → 环境变量 → 缓存未过期 access_token → **refresh_token 续期** →
`token.local.txt`（兼容旧用法）→ `client_credentials`。

命令行：`--check`（体检）/ `--login`（拿 18 个月 refresh token）/ `--code` /
`--refresh` / `--save-user-token`。

**`--check` 会真打一次 Browse API**，不只检查"文件里有没有字"：
`token.local.txt` 里躺着一个过期令牌，只看"文件非空"会误报健康 ——
**"读到一个令牌字符串" ≠ "这个令牌能用"**。

### 二、实测：两条路现在都不通（诚实记录）

production 和 sandbox **都**报 `invalid_client`。

**根因（拿用户提供的开发者后台截图逐字比对后确认）** —— `config.local.json` 两个字段都填错了：

| 字段 | 应填 | 实填 | 问题 |

| `client_id` | 与目标环境一致的 App ID | `BETA-SBX-…-d079` | **沙箱** App ID，却打 production |

### 三、**踩了两个真坑**（都只在"换环境"时才暴露）

**坑 1：bat 里的中文路径受 cmd 代码页支配。**
第一版把代码放 `关键词选品\脚本\`、bat 里写中文路径，本机测试直接报"找不到采集脚本"
（我的控制台代码页是 **65001**，GBK 写的 bat 被按错误代码页解析）。改成：

与代码页无关。

**坑 2：`dtype == object` 在 pandas 3.0 上失效。**
eBay 的 `description` 是整页 HTML（实测最长 **310,582 字符**），远超 Excel 单元格上限 32767，
不处理会**每条**吐一个 UserWarning，把 bat 窗口刷爆（实测 18 条警告）。
第一版用 `if df[col].dtype == object` 挑字符串列 —— 本地 pandas 2.1.4 测着没问题，
但**共享目录的运行时的 pandas 是 3.0.3，字符串列 dtype 已经变成 `str`**，
判断全部失效、警告照旧。改为"该列只要有字符串就处理"，与 dtype 无关。
→ 教训：**部署环境的依赖版本要真跑一遍才算验证过**（我用共享运行时复现才定位到）。

顺带把超长单元格做成显式截断并标注：`…【已截断，原文 310582 字符，完整内容见同名 .json】`
（实测 200 条里 32 条 description 被截断；完整原文在同名 .json 里）。

**坑 3：关键词里的隐形字符。**

**坑 4（不是 bug，但差点误判）：`cmd /c bat` + 重定向 stdin 会立刻 EOF。**

**两行的最小 bat 也一样**，直接跑 python 则正常 —— 这是 Windows 的行为，与程序无关。
真正的验证方式是用 `start` 开一个**全新控制台**（等同双击）：实测进程 6 分钟后仍活着，
说明它正阻塞在 `input()` 等键盘，交互可用。

> 教训：**测试方法本身也会骗人**。结论站不住时，先用最小复现把"是我的问题"
> 和"是环境/工具的问题"分开，再下判断。

### 三、这为什么重要

| 项 | 结论 |
|---|---|
| 合规性 | ✅ **官方 API**，不是爬页面、不碰私有端点 |
| 授权门槛 | ✅ **app token 即可**（应用级 scope），**不需要 RuName / 卖家授权** |
| 审批 | ✅ **不需要任何审批**（额度已在我们的额度表里：`commerce.feedback` 5000/天） |
| 覆盖范围 | ⚠️ **只覆盖"留了评价的订单"** → 相对指标，不是绝对销量 |
| 时间粒度 | ⚠️ 只有 `LESS_THAN 90 DAY` 这类窗口，**无精确成交日期** |
